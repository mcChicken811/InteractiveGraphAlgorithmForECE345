BFS · Graph Builder

    • Click empty space to add a node.
    • Click a node, then another to connect them.
    • Click an edge to delete it.
    • Drag a node to move it.
    • Right-click a node (or select it and press Delete) to remove it.
    • Esc or click empty space to cancel a selection.
    • Randomise (top) makes a random graph on an empty canvas, or random edges between the nodes you have placed, of the kind selected: Directed may join two nodes both ways, Weighted gives weights from 1 to 20, and Unweighted leaves every weight at 0.
    • Auto-layout (top left) spaces the graph out automatically.
    • Undirected / Directed (top left) sets how edges are read. Clicking A then B always records A → B; undirected mode ignores the direction.
    • Unweighted / Weighted (top left) shows or hides edge weights (default 0). In weighted mode, scroll over an edge to change its weight (up = more).
    • Run (top right) simulates the chosen algorithm, starting from the selected node (or node 0). Update takes one step; Stop or Finish ends it. The graph is locked while it runs.
    • While BFS runs, vertices show their distance from the start (blank until found). Hover the queue to see their numbers again. Edges are dashed, except each vertex's edge to the vertex it was discovered from (its predecessor), which turns solid. Show as tree arranges the vertices as the tree found so far, by distance from the top, with the vertices not reached yet waiting on the right; each Update brings newly found vertices into the tree. Press it again, or turn on Auto-layout, to leave it.
    • DFS reads the graph as directed. Vertices show their discovery, finish times (yellow: running, green: finished). Edges stay dashed until explored, then are labelled forward, backward or crossed (tree edges are plain). Hover the stack to see the vertex numbers. The Timestamps card charts each vertex from discovery to finish; hover it and press the corner button to view it full size.
    • Prim's algorithm reads the graph as undirected and grows a minimum spanning tree from the start node (green vertices and edges; other edges are dashed). Vertices shrink to small dots; hover the priority queue to grow them back and see their keys: the lightest edge found so far joining them to the tree (∞ if none). It uses the edge weights in weighted mode, and counts every edge as 1 in unweighted mode.
    • Kruskal's algorithm also builds a minimum spanning tree, but edge by edge: it takes the edges lightest first (the Sorted edges card) and keeps each one that joins two separate trees. The white edge is the next one; hover the sorted edges to see which set (tree) each vertex belongs to. Each tree so far is shaded green as a territory of its own, with a border between trees. Edges not in the forest are dashed; those still to check inside one tree are a darker green.
    • When DFS is done, Topological sort lines the vertices up by decreasing finish time. Tree edges run along the line in white; the other edges arc above (forward) or below (crossed). If DFS found a cycle there is no topological order: the backward edges, pointing right to left, arc below in red. Auto-layout leaves this view; press the button again to come back.
    • While DFS runs, Show as forest arranges the vertices as the depth-first forest so far, laid out like the timestamp chart: one row per depth, each vertex above the middle of its [d, f] interval ([d, now] while it runs). Vertices not discovered yet wait on the right, and each Update brings new ones in. Once DFS is done, tree edges turn white and it switches with Topological sort. Press it again, or turn on Auto-layout, to leave it.
    • While any algorithm runs, hover the adjacency list or matrix to see the vertex numbers on the canvas.
    • Messages appear at the bottom and slide away after 5 s; move the mouse to the bottom edge to bring the last one back.
